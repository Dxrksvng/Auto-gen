# แผนทดสอบการใช้งาน (Usability Test Plan) สำหรับระบบสร้างเอกสารจากไฟล์ Excel

**สถานะ:** แผนเท่านั้น **ยังไม่ได้ทดสอบกับใคร ไม่มีผลลัพธ์ให้อ้าง** ห้ามใส่ตัวเลขผลทดสอบในเอกสารอื่นจนกว่าจะทดสอบจริง
**วันที่เขียน:** 2 ตุลาคม 2569
**สิ่งที่ทดสอบ:** คู่มือผู้ใช้ (`as3/USER_GUIDE.md`) คู่กับหน้าจอตัวอย่าง (`as3/mockup/`) ระบบจริงยังไม่มี การทดสอบนี้จึงวัดว่า **คู่มือและหน้าจอที่ออกแบบ** เข้าใจได้ไหม ไม่ใช่วัดระบบที่ทำงานจริง

## 1. วัตถุประสงค์

1. คนที่ไม่ใช่สายเทคนิคทำงานหลักสำเร็จได้ด้วยคู่มือ โดยไม่ต้องมีคนช่วยหรือไม่
2. ผู้ใช้เข้าใจป้ายสถานะและข้อความที่ระบบแสดง และรู้ว่าต้องทำอะไรต่อหรือไม่
3. รายการตรวจก่อนส่งจดหมายให้ลูกค้า จับข้อผิดพลาดที่ตั้งใจใส่ไว้ได้หรือไม่
4. จุดไหนในคู่มือหรือหน้าจอที่ทำให้สับสน

## 2. ผู้เข้าร่วม

- **3 ถึง 5 คน** (แผนเสนอ ไม่ใช่การวัดทางสถิติ ใช้หาปัญหาการใช้งาน ไม่ใช้ประมาณสัดส่วนของประชากร)
- เป็นพนักงานอายุราว 35 ถึง 40 ปี ใช้ Microsoft Office, Google Workspace และอีเมลเป็นประจำ **ไม่มีพื้นฐานโปรแกรมมิ่ง**
- ไม่ได้มีส่วนร่วมออกแบบระบบหรือคู่มือ
- ควรมีทั้งคนที่เคยทำงานคล้ายกับงานเอกสารลูกค้า และคนที่ไม่เคย **[TO CONFIRM: ใครคือผู้ใช้เป้าหมายจริง และวิธีหาผู้เข้าร่วม]**
- ขอความยินยอมก่อนเริ่ม แจ้งว่าทดสอบ "คู่มือและหน้าจอ" ไม่ใช่ทดสอบตัวบุคคล และหยุดได้ทุกเมื่อ

## 3. สิ่งที่ต้องเตรียม

| รายการ | รายละเอียด |
| --- | --- |
| คู่มือ | `USER_GUIDE.pdf` (พิมพ์หรือเปิดบนจอ ตามที่ผู้ใช้จะใช้จริง) |
| หน้าจอตัวอย่าง | เปิด `mockup/index.html` ผู้ทดสอบคลิกเดินไปมาตามขั้นตอน |
| ไฟล์ Excel | ทั้ง 3 ไฟล์ใน `as3/examples/` และชุดข้อมูลบนกระดาษสำหรับให้กรอก (ข้อมูลสมมติ) |
| จดหมายตัวอย่างสำหรับงานตรวจ | จดหมาย PDF 3 ฉบับ โดยตั้งใจใส่ข้อผิดพลาด 2 จุด **[ข้อเสนอ]** เช่นเลขกรมธรรม์ไม่ตรงกับไฟล์ และมีคำว่า "คุณ" ซ้ำ ผู้ทดสอบต้องสร้างให้ตรงกับข้อผิดพลาดที่ต้องการวัด |
| ผู้ร่วมทดสอบ | ผู้ดำเนินการ 1 คน (พูดตามบท ไม่ชี้แนะ) และผู้จดบันทึก 1 คน |
| ข้อมูล | ใช้ข้อมูลสมมติเท่านั้น ห้ามใช้ข้อมูลลูกค้าจริง |

## 4. งานที่ให้ทำ (Tasks)

บทพูดของผู้ดำเนินการ: ให้ผู้เข้าร่วมพูดสิ่งที่คิดออกเสียง ถ้าติดเกิน **เวลาจำกัด** ให้ถามว่าคิดว่าต้องทำอะไร ให้คำใบ้ได้ตามลำดับที่กำหนด และจดจำนวนคำใบ้ เวลาจำกัดด้านล่างเป็น **ข้อเสนอ ต้องตกลงก่อนทดสอบ**

| งาน | สิ่งที่ผู้เข้าร่วมต้องทำ (บอกเป็นเป้าหมาย ไม่บอกวิธี) | เวลาจำกัด | เกณฑ์สำเร็จ |
| --- | --- | --- | --- |
| T1 | เริ่มงานสร้างจดหมายขอเอกสารเพิ่มเติม และได้ไฟล์แม่แบบมา | 3 นาที | กดเริ่มรอบงานใหม่ และดาวน์โหลดไฟล์แม่แบบได้ โดยไม่ต้องมีคำใบ้ |
| T2 | กรอกข้อมูลลูกค้า 3 ราย (จากกระดาษ) ลงในไฟล์แม่แบบ รวมช่องรายการเอกสาร | 10 นาที | ไฟล์ที่ได้ผ่านการตรวจด้วยตัวตรวจ A2 โดยไม่มีรายการที่ต้องแก้ |
| T3 | อัปโหลด "ไฟล์ฝึกแก้ไข" อ่านรายการที่ต้องแก้ แก้ให้ครบ แล้วอัปโหลดใหม่ให้ผ่าน | 10 นาที | แก้ครบ 3 จุด (แถวที่ 4, 6, 7) ภายในเวลา โดยแก้เฉพาะในไฟล์ Excel ไม่แก้ที่อื่น |
| T4 | ตรวจจดหมายตัวอย่าง 3 ฉบับตามรายการตรวจก่อนส่ง แล้วตัดสินใจว่าจะขออนุมัติหรือไม่ | 8 นาที | พบข้อผิดพลาดที่ตั้งใจใส่ไว้ครบ และไม่กดขออนุมัติทั้งที่ยังมีข้อผิดพลาด |
| T5 | ดูภาพข้อความ 6 ข้อความ (สุ่มเลือกจาก catalog ให้ครอบคลุมระดับไฟล์ แถว สร้างจดหมาย ซ้ำ อนุมัติ) แล้วบอกว่า "หมายความว่าอะไร และต้องทำอะไร" | 6 นาที | บอกการกระทำถัดไปได้ถูกต้องอย่างน้อยตามที่กำหนด **[TO CONFIRM: เกณฑ์เช่น กี่ข้อจาก 6]** |
| T6 | ถ้าอัปโหลดไฟล์เดิมซ้ำและระบบขึ้น "ซ้ำกับรอบงานก่อนหน้า" ให้จัดการ | 5 นาที | เลือกวิธีจัดการและเขียนเหตุผลได้ และอธิบายได้ว่าเลือกแล้วจะเกิดอะไร |

**ลำดับคำใบ้ (จดทุกครั้ง):** (1) ถามว่ากำลังพยายามทำอะไร (2) ชี้ให้ดูหัวข้อของคู่มือที่เกี่ยวข้อง (3) บอกขั้นตอน การได้คำใบ้ระดับ 3 นับว่า "ทำไม่สำเร็จด้วยตนเอง"

## 5. สิ่งที่วัดและบันทึก

| ตัวชี้วัด | วิธีบันทึก |
| --- | --- |
| ความสำเร็จต่องาน | สำเร็จเอง / สำเร็จโดยมีคำใบ้ / ไม่สำเร็จ |
| เวลาต่องาน | วินาที (ผู้จดบันทึกจับเวลา) |
| จำนวนคำใบ้และระดับ | นับ |
| การคลิกผิดหรือเปิดหัวข้อผิดในคู่มือ | นับและจดว่าที่ไหน |
| ความเข้าใจข้อความ (T5) | ผู้เข้าร่วมบอกการกระทำถัดไป เทียบกับคอลัมน์ "ต้องทำอะไร" ของ catalog |
| ความมั่นใจหลังแต่ละงาน | คะแนน 1 ถึง 5 ตอบเอง |
| ข้อสังเกตและคำพูดของผู้เข้าร่วม | จดตามที่พูด ไม่ตีความ |

คำถามหลังจบ: (1) ส่วนไหนของคู่มือที่ไม่เข้าใจ (2) คำไหนที่ไม่คุ้น (3) อะไรที่คาดว่าจะมีแต่ไม่มี (4) จะใช้คู่มือนี้จริงหรือไม่ และเปิดตอนไหน

## 6. เกณฑ์ตัดสินว่าคู่มือ "ผ่าน" **[ข้อเสนอ ต้องตกลงก่อนทดสอบ]**

- งาน T1, T3, T4 ผู้เข้าร่วมส่วนใหญ่สำเร็จเองโดยไม่มีคำใบ้ระดับ 3 **[TO CONFIRM: ส่วนใหญ่ = กี่คนจากกี่คน]**
- T4: ไม่มีผู้เข้าร่วมที่ปล่อยข้อผิดพลาดที่ตั้งใจใส่ไว้ผ่านไปโดยกดขออนุมัติ (เพราะเป็นความเสี่ยงต่อลูกค้า) ถ้ามี ต้องแก้คู่มือหรือรายการตรวจก่อน
- ปัญหาเดียวกันที่เกิดกับ 2 คนขึ้นไป ต้องแก้และทดสอบรอบใหม่

## 7. การวิเคราะห์และการแก้ไข

- สรุปปัญหาเป็นรายการ จัดความรุนแรง: (ก) ทำให้ส่งจดหมายผิด (ข) ทำให้ทำงานไม่สำเร็จ (ค) ทำให้ช้าหรือสับสน
- แก้ไขคู่มือและ `docs/message-catalog.json` (แหล่งความจริงเดียวของข้อความ) แล้วสร้างคู่มือและ mockup ใหม่ด้วย `scripts/build_guide.py` และ `scripts/build_mockup.py` และรัน `scripts/check_guide_words.py` กับ `scripts/check_a2_a3.py`
- ทดสอบซ้ำกับผู้เข้าร่วมกลุ่มใหม่หลังแก้

## 8. ข้อจำกัดที่ยอมรับล่วงหน้า

- ทดสอบกับ mockup ไม่ใช่ระบบจริง พฤติกรรมจริง เช่น ความช้า ข้อผิดพลาดที่ไม่คาดคิด จะยังไม่เห็น
- ผู้เข้าร่วมจำนวนน้อย ใช้หาปัญหา ไม่ใช่วัดอัตรา
- ผลขึ้นกับผู้เข้าร่วมและผู้ดำเนินการ ต้องใช้บทพูดเดียวกันทุกคน
